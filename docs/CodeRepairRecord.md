# FluentFlyout 修复记录

> 本文按**最终形态**整理：同一个问题如果经历过多轮迭代（先修了一半、后来又补齐），这里合并为一条完整的「现象 → 原因 → 修复」，不保留中间过程。
> 完整分析（含"哪些激进手段是平台所迫、不算缺陷"）见 [CodeAnalysis.md](./CodeAnalysis.md)。

## 一、设置与持久化

| 问题 | 根因 | 修复 |
|---|---|---|
| 设置保存可能静默丢数据 | 临时文件名固定、`File.Replace` 放在锁外的 `Task.Run` 里，两次保存会互相覆盖/删掉对方的临时文件 | 临时文件改为每次唯一（`{path}.{guid}.tmp`），写入与替换全部放进同一把锁内同步完成 |
| 退出前最后 500 ms 的设置必丢 | 「退出前保存」被整段注释（注释自认存在 race） | 恢复保存；清理路径用 `Interlocked` 幂等守卫，保证只跑一次 |
| 清理流程执行两遍、`NLog.Shutdown()` 提前执行 | `OnClosed` 与托盘「退出」各调一次 `CleanupResources` | 同上，`int` + `Interlocked.Exchange` 幂等 |
| 一个坏的语言值导致整份设置被重置 | `OnAppLanguageChanged` 用会抛异常的 `First()` 且无初始化守卫 → 反序列化失败 → 丢弃主文件 → 备份同样坏值 → 新建默认设置 | 改 `FirstOrDefault` + 回落 `en-US` + 警告日志 |
| 界面「变更检测」缓存永远停在默认值 | 缓存字段在字段初始化阶段取值，早于 `RestoreSettings()`，而 Current 实例会被整体替换 | 新增 `SyncSettingsSnapshot()`；主题比较改为比较**实际应用**的主题而非设置值 |
| 保存/替换发生在 UI 线程（长锁时卡顿） | 为保证写入顺序，替换被刻意留在锁内与调用线程上 | **属刻意取舍**，不视为缺陷；文档注明代价即可 |

## 二、媒体会话与图标

### 点击播放/暂停后图标延迟约 10 秒（合并多次迭代）

**现象**：点媒体浮窗或任务栏小组件的播放/暂停，图标长时间不切换；连续点第二次时干脆"不动"，要等十几秒才跳到正确符号；浮窗自动隐藏后再唤出，显示的仍是点击前的图标。

**原因**：Windows 在播放器上报之前会一直重复**命令之前**的状态。原来的图标完全由"播放器上报"驱动，点击后既不乐观更新也不回读；而用"当次读到的状态"去推导目标状态时，连点读到的仍是旧值，于是算出的目标与当前图标相同。

**修复**：以**应用自己发出的命令**作为即时真值 ——

- 命令成功后按当前解析状态推导目标状态，立即更新浮窗与小组件两处图标；
- 记录「命令要求的状态 / 发命令时 Windows 重复的陈旧值 / 时间戳」：只要 Windows 报的仍是那个陈旧值就沿用命令状态，一旦报出**不同**值或超过 20 秒信任窗就采纳 Windows 的值；
- 1.5 秒后回读校正一次；换歌、切换会话、按下播放/暂停媒体键都作废该状态（这三种情况无法从值上区分）。

| 问题 | 根因 | 修复 |
|---|---|---|
| 右键「打开媒体播放器」点了完全没反应 | 缓存的进程 ID 只按最近使用淘汰、无过期时间；播放器退出后缓存指向已消失的进程，失败后也不清缓存 → 永远卡在同一条失效记录 | 检测到进程失效时清除该条缓存并重新解析一次；失败会在日志里留下明确原因 |
| 同上：取不到窗口句柄时的兜底从未生效 | 该兜底排在抛出异常之后，属死代码 | 缓存失效路径改为"重新解析"，兜底才真正可达 |
| 封面每次都要重读整条流 | 即使缓存命中，`GetThumbnail` 仍先读流 + `SHA256` 才查缓存 | 新增"一次读取"入口（哈希与解码共用同一份字节），缓存命中不再重读 |
| 读媒体属性时卡住 UI | `TryGetMediaPropertiesAsync().GetAwaiter().GetResult()` 在 UI 线程同步阻塞 | 新增 `UpdateUIAsync`：先在后台读完再进 dispatcher；媒体回调线程仍用同步版本 |
| 进程与句柄泄漏、缓存无上限 | `Process.GetProcesses()` 从不释放；按标题为键的缓存无上限；Shell COM 引用不释放 | 释放进程快照、缓存加 64 条 LRU、COM 引用在 `finally` 中显式释放 |
| 判空逻辑错位（死代码） | 已取 `ControlSession` 之后又判断 `mediaSession == null` | 删除错位判断，保留对 `ControlSession` 的判空 |

## 三、主题与窗口外观

### 切换「应用主题」后设置窗口空白、侧边栏错位、甚至退出（合并多次迭代）

**现象**：切换「应用主题」后，设置页内容整片空白（必须切走再切回）、侧边栏整体右移 96px（展开）或 201px（收起）、展开按钮点了没反应、之前能看到的内容"上移一下再回原位"；「跟随系统」时在 Windows 里切深浅色，当前页同样消失；最严重时点两次收起按钮后程序直接退出。

**原因**（一条因果链）：

1. 切主题会换掉 WPF-UI 的主题字典；MicaWPF 在刷新时会遍历整个窗口重设每个元素的 `Style`（`element.Style = new(); UpdateDefaultStyle(); Style = saved`）。`NavigationView` 是 `OverridesDefaultStyle`、模板只由样式提供，于是被留在**无模板**状态 —— 面板与窗口 chrome 不再渲染（用户看到的"空白"）。
2. 陈旧的状态组仍带着按模板元素名解析的过场动画，下一次面板开合就在 `FindNameInTemplateContent` 抛 `NullReferenceException`，该异常逃到 dispatcher 即结束进程；异常还打断了后面的赋值，使「展开」请求的值等于当前值 → 按钮看起来失效。
3. MicaWPF 那个空 Style 让模板根的两列都回落为 `*`，面板在半个窗口里居中 → 右移 96 / 201px。
4. 模板重建后新 `Frame` 是空的，而 WPF-UI 把"导航到当前页类型"视为 no-op → 内容区一直空白，直到手动切页。
5. 设置窗口不是 `Application.MainWindow`，WPF-UI 切主题时**只刷新主窗口**的 DWM 背板 → 设置窗口的云母停留在创建时的主题（发白发平），要重开 GUI 才恢复。

**修复**：

- 主题变化后按两个时机修复导航视图（`DispatcherPriority.DataBind`：资源已换、渲染之前；`DispatcherPriority.Loaded`：布局已完成）：清掉被顶掉的 `Style` → 强制重新解析隐式样式 → 手工应用面板视觉状态（**不带过场动画**，从根上避开那条 NRE）→ 用零时长 `HoldEnd` 动画把重建后的面板宽度钉死；
- 重建后重挂当前页（先跳中转页再跳回，绕过 no-op），并让缓存里失效的 `ScrollViewer` 失效；
- 重建窗口内把 `OpenPaneLength` 临时压到紧凑宽度，消除"展开再收起"的宽度扫动与条目区 6px 跳动；
- 用代际计数把"属性变更 + 主题事件"两次上报合并成一次修复；
- 订阅 `ApplicationThemeManager.Changed` 覆盖"跟随系统"路径；
- **顺带**：新增 `RefreshWindowBackdrop()`，做一次新窗口在 `SourceInitialized` 时该做的事（重设 DWM 背板），设置窗口的云母即时跟随；
- 兜底：只吞掉这一条已知的 NavigationView 视觉状态 NRE，其余 dispatcher 异常照旧致命。

### 切换系统深浅色后，媒体浮窗只有背景没换（合并多次迭代）

**现象**：切系统深浅色之后（机器休眠过几次后尤其容易出现），文字与图标已是新主题，背景还是旧主题的底色；通常再切一次主题就恢复。

**原因**：文字来自主题资源字典，换主题会自动跟随；背景是**一次性烘进窗口**的亚克力色调（`AccentPolicy.GradientColor`），写入的是当刻的背景色。原先只在"检测到主题值发生变化"时重烘一次，而这次重烘可能正好落在主题资源还没换完的瞬间 —— 于是记下了新主题、却烤进了旧颜色，之后不再重试。系统主题变化、DWM 重组、休眠唤醒都没有重涂入口。

**修复**：不再依赖"检测变化" —— 每次唤出前按当前颜色无条件重烘；主题事件到达后再烘一次（渲染前）；DWM 重组、从睡眠恢复、解锁会话各补一次；并且只有**真正施加成功**后才记录"已应用"，失败不会被当成已完成。

| 问题 | 根因 | 修复 |
|---|---|---|
| 亚克力在某些系统上不生效、背景色写死 | 只走未公开 API，无降级链；背景色硬编码两个常量 | Win10 1803 以下降级为普通模糊；背景色改为优先取主题实际画刷，取不到才用常量 |
| 主题订阅重复、无法解绑 | `UnWatch` 在窗口未加载时提前返回 → 订阅留下却永不解除 | 新增"是否正在监听"状态位，订阅/解绑都幂等 |
| 切主题后设置页被强行踢回首页、匿名 lambda 永不释放 | 每次主题变化都导航到首页；处理器是匿名 lambda | 改为回到**用户当前页**；处理器存入字段并在窗口关闭时退订 |
| 窗口类型靠字符串匹配 | 用 `GetType().Name` 判断该不该上亚克力 | 改为类型 `switch`（重命名/派生不会静默失效） |

## 四、音量浮窗与原生音量 OSD

### 音量浮窗位置：空洞、居中、以及冷启动第一次错位（合并多次迭代）

**现象**：

1. 开「排除音量键」+「音量浮窗展示在媒体浮窗上方」时，用快捷键或滚轮调音量，音量浮窗离任务栏空出一大截，空洞高度正好等于一个媒体浮窗；
2. 空洞修掉之后，它又落在**屏幕水平居中**的位置，而不是任务栏小组件的正上方（小组件在左侧时尤其明显）；
3. 冷启动后**第一次**唤出，它落在系统默认位置、并且没有模糊。

**原因**：

1. "叠在媒体浮窗上方"只判断**设置开关**，没有判断媒体浮窗**此刻是否真的在屏幕上**。「排除音量键」开着时音量键不会唤出媒体浮窗（滚轮那条路径也从不唤出它），可位置仍按"媒体浮窗在这儿"预留了它的高度。
2. "贴任务栏"使用的公共定位分支一律按**屏幕宽度的一半**居中，与小组件实际在哪无关。
3. 这个浮窗所有定位与着色都通过 Win32 完成，而它在第一次 `Show()` 之前**没有窗口句柄** —— 那些调用全部静默失败，窗口于是由系统按默认位置摆出来（锁键浮窗同理：它构造与首次显示在同一轮 dispatcher 里）。

**修复**：

1. 判定改为「媒体浮窗**真的在屏幕上**，或**本次触发确实会唤出它**」才往上叠，否则退回任务栏上方；
2. 新增「以任务栏小组件的屏幕矩形为水平锚点」的定位：浮窗以小组件为中心，并夹在工作区内（贴边时不越界）；取不到小组件（未启用/被隐藏）时回退居中；
3. 两个窗口构造时 `EnsureHandle()` 提前建好句柄（窗口仍不可见）；
4. 已经单独显示的音量浮窗，在媒体浮窗**刚**出现时自动挪到它上方，并用标记避免"媒体浮窗异步到达"造成的二次动画。

现在的行为：

| 排除音量键 | 触发 | 音量浮窗位置 |
|---|---|---|
| 开 | 快捷键 / 滚轮 | 任务栏小组件正上方（离任务栏 16px） |
| 关 | 快捷键 | 媒体浮窗出现，音量浮窗叠在**媒体浮窗**上方 |
| 关 | 滚轮 | 媒体浮窗不在屏上时同上第 1 条；恰好在屏上时叠在它上方 |

| 问题 | 根因 | 修复 |
|---|---|---|
| 枚举原生音量 OSD 的循环永不退出 | 每轮都从游标 0 重新枚举，三处 `continue` 不推进游标 → 命中首个窗口后死循环；后台线程永久空转，原生 OSD 也不再恢复 | 游标改为"上一轮命中的句柄"，并加最大迭代上限 |
| 多显示器混合 DPI 下参照矩形算错 | 用音量浮窗所在屏的 DPI 换算媒体浮窗的宽高 | 改用**参照窗自己所在显示器**的 DPI |
| 拔耳机/播放器退出时程序直接消失 | 音量浮窗显示期间每 100 ms、混音器每秒读一次音频设备，COM 失效时抛异常，而这几条读取路径没有保护；异常逃到 UI 线程即结束进程 | 三处读取补上异常保护（记日志 + 让浮窗自行收起）；设备变更回调也补判空与保护 |

## 五、任务栏小组件与可视化

| 问题 | 根因 | 修复 |
|---|---|---|
| 小组件浮在桌面上、盖住一切 | `SetParent` 在任务栏尚未就绪（空句柄）时仍执行 —— 传 NULL 会把窗口改挂到桌面 | 新增"附加到任务栏"入口：空句柄时不挂载，挂载后用 `GetParent` 校验，失败等下一次轮询重试 |
| UI 线程最坏卡 1.5 秒 | 用 `Task.Wait(1000)` / `Wait(500)` 等 UI Automation 查询 | 改为 `async` + `WaitAsync(timeout)`，超时即放弃并重试 |
| 可视化偶发崩溃（进程级） | 采集线程按静态 `BarCount` 索引一个会被重建的数组；采集回调无 try/catch | 数组改为"永不原地扩容、原子发布新快照"，读者按自身长度遍历；采集回调整体包异常保护；`Stop()` 先取字段快照再释放 |
| 切换输出设备后可视化冻住 | 看门狗判据是"静默超过 2 秒"，但计时器只在最后一帧后响一次（500 ms）且 `AutoReset=false` → 永远达不到阈值，自恢复从未生效 | 看门狗改为在静默窗口内反复自我重武装，直到真正超过 2 秒才重启采集（仍由第一帧音频数据启动，避免"没在放音频"被误判） |
| 音频帧无界堆积 | 每帧都 `InvokeAsync`，UI 落后时队列无限增长且画的是同一份过期数据 | 新增"只保留一帧"的合并标志 |
| 关闭可视化再打开后画面不动 | 释放后静态字段仍指向已释放实例，`if (visualizer == null)` 恒假 | 允许为 null，释放后置空，重启用时重建实例 |
| 手改设置文件传 0/负数会崩 | `new float[负数]`，且有一处恒真的死分支 | 条数夹取到 1–20 |
| 改「小组件目标显示器」不立即生效 | 其它布局类设置都会触发重算，唯独这一项没接 | 补上刷新钩子 |

## 六、键盘与锁键

| 问题 | 根因 | 修复 |
|---|---|---|
| 连按媒体键会卡顿、钩子可能被系统摘掉 | 低级键盘钩子回调里直接做 COM 音量同步与系统通知状态查询（超过 `LowLevelHooksTimeout` 会被静默摘钩） | 钩子回调只做"识别键 → `PostMessage` → `CallNextHookEx`"，判定逻辑全部移到 UI 线程 |
| 英文界面下锁键浮窗被压扁 | 宽度测量被放在 `if (languageCode == "en") return;` **之后**，英文下永不执行，`maxLength` 保持 0 | 把测量提到提前返回之前（非英文的测量时机另见遗留项） |
| Insert 提示永远显示为"开启"外观 | `isOn` 参数被 `isOn = true` 覆写，`false` 分支不可达且原因不明 | 用显式 `isInsertKey` 表达"Insert 无状态可读"这一既有意图 |

## 七、启动、托盘与链接

| 问题 | 根因 | 修复 |
|---|---|---|
| 开机启动出现两套机制、可能双启动 | 注册表 `Run` 与 MSIX 启动任务同时存在 | 收敛为单一机制（注册表 `Run`），并清理旧打包版留下的指向 `WindowsApps` 的旧值；开关回显系统真实状态 |
| 导入设置后重启可能 NRE | 重启前用 `Process.GetCurrentProcess().MainModule.FileName` | 改用 `Environment.ProcessPath`，取不到就记日志跳过 |
| 点设置里的「打开设置页」链接可能让程序退出 | `ms-settings:` 的 `Process.Start` 无异常保护 | 两处链接都加保护，失败只记日志 |
| Explorer 重启后托盘图标消失 | 注册状态必须显式重建 | 收到 `WM_TASKBARCREATED` 后先等任务栏出现几何，再重建图标（最多 60 秒） |

## 八、本地化

| 问题 | 根因 | 修复 |
|---|---|---|
| 欢迎界面中英混杂 | 启动顺序把本地化放在窗口构造之后；而欢迎页在字段/属性初始化器里就把字符串**快照**成了英文 | 把"显示欢迎页"移进本地化之后；perk 文本改用 `DynamicResource`；并记录"坏字典"的具体错误 |

| 20 多种语言长期缺键、半英半本地 | 翻译欠账 + 只保留有维护的语言更划算 | 收敛为 English / 简体中文 / 繁体中文，并补齐繁体缺失的 34 条译文（三份字典键集合一致，各 272 键） |

## 九、工程、构建与发布

| 问题 | 根因 | 修复 |
|---|---|---|
